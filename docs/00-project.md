# Паспорт проекта ProCaloryAI

## Название и происхождение

ProCaloryAI — собственный проект Каменского Андрея Игоревича, группа БПИ2301. Сервер дневника питания с будущим анализом фотографий еды.

## Назначение и решаемая проблема

Пользователю нужно записывать питание и понимать, сколько калорий, белков, жиров и углеводов он получает за день. Проект хранит дневник, считает статистику и позволяет задать цель снижения веса.

## Пользователи и роли

| Роль или участник | Назначение |
| --- | --- |
| Владелец аккаунта | Ведёт свой дневник, смотрит статистику, меняет цель и настройки |
| Внешний AI Core | Планируется: получает фотографию и возвращает название и КБЖУ блюда |

Гость может зарегистрироваться и войти. Это состояние доступа основной роли, а не отдельная роль. Требование курса выполняется связкой «пользователь + внешняя система». Сейчас внешний Core не подключён. Значение admin есть в коде, но административные функции в объём семестра не входят.

## Три основные функции сейчас

1. Регистрация и вход в личный аккаунт.
2. Ручное ведение дневника и просмотр статистики питания.
3. Установка цели снижения веса и просмотр расчётного прогресса.

## Сущности

Основная модель: User — пользователь; MealLog — запись питания; Goal — цель; AnalysisRequest — запрос анализа; Preferences — предпочтения. PrivacySettings хранит вспомогательные настройки. Dish не используется текущей ORM.

### Внешние зависимости, хранение и настройки

В первой работе нужны backend и PostgreSQL. Данные хранятся в именованном Docker-томе. Библиотеки закреплены uv.lock, настройки передаются переменными окружения из Compose и .env. Пример настроек — .env.example. Фотоанализ отключён, поэтому Kafka, MinIO и Core не нужны.

## Журнал запуска

| Проблема | Решение |
| --- | --- |
| Часть мутаций использовала user.id для словаря | Единый доступ user["id"] |
| Ошибка SQL и делителя недельной статистики | Календарное окно в 7 дней, включая пустые |
| Backend ожидал Kafka без Core | Режим PHOTOS_ENABLED=false |

На macOS в чистых Linux-контейнерах проверены сборка, миграции, 11 API-тестов и сохранение записи после перезапуска. Сценарий запуска и протокол находятся в README.
